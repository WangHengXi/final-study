## Context

目前 `CourseListView` 會篩選目前使用者的課程，並把完整 queryset 渲染到初始課程列表 HTML。頁面搜尋是一般 GET 表單，專案中也沒有可重用的 AJAX 列表或分頁慣例。此變更在列表頁與課程資料之間建立 JSON 邊界，但保留課程詳情與建立課程的既有流程。

## Goals / Non-Goals

**Goals:**

- 不重載整個頁面即可搜尋及瀏覽分頁課程。
- 定義只公開目前使用者課程的穩定、需驗證的 JSON 契約。
- 讓載入、空結果與失敗狀態可區分，並可由鍵盤及輔助技術使用。
- 記錄未來後端資料列表可重複採用的規範。

**Non-Goals:**

- 不變更課程模型、擁有權規則、課程詳情路由或建立課程流程。
- 不加入排序選項、無限捲動、用戶端快取、背景更新或通用 JavaScript 框架。
- 不把靜態導覽清單或初始 HTML 已完整提供內容的非資料清單改為 AJAX。

## Decisions

### 專用同源 JSON 端點提供分頁課程

在 learning 應用新增 `GET /learning/courses/data/` 端點。端點在套用既有課程名稱搜尋前先依已驗證使用者篩選，沿用模型目前由新到舊的排序，並回傳供課程卡片直接使用的精簡 JSON 與分頁資訊。格式錯誤或非正數的頁碼回傳 JSON 400，匿名呼叫回傳 JSON 401。

獨立端點能讓頁面外殼持續可導覽，且可獨立測試資料結果。回傳適合顯示的資料能避免瀏覽器端重複建立 Django URL 或個人檔案顯示名稱的備援邏輯。把 HTML 列表回應當作 API 的做法被排除，因為它會把用戶端渲染綁死於模板標記，並使狀態處理不明確。

### 頁碼分頁固定每頁 10 筆

端點每頁最多回傳 10 筆，並提供 `page`、`page_size`、`total_count`、`total_pages`。瀏覽器依頁碼請求，且只有在可移動時才呈現上一頁、下一頁與可用頁碼控制項。頁碼分頁取代無限捲動，因為它提供可定位的 URL 與可預測的鍵盤操作；以游標分頁處理目前的課程模型及頁面範圍並無必要。

### 瀏覽器負責列表呈現與 URL 狀態

初始課程列表回應提供標題、搜尋控制項、狀態區、空狀態與錯誤容器，以及列表容器，但不含由伺服器預先輸出的課程卡片。頁面專屬的小型 script 呼叫資料端點、渲染卡片和分頁，並在成功請求後以 History API 更新 `q`、`page`。瀏覽器上一頁／下一頁會依 URL 狀態重新發出請求。

伺服器負責驗證、篩選、排序及分頁；瀏覽器負責暫態顯示狀態。完整頁面提交表單的方式被排除，因為這正是此變更要移除的互動。

### 載入與失敗保留可用內容

首次請求時，在列表區顯示載入指示並以可存取的 busy／status 公告。後續請求期間，保留目前成功卡片、停用會重複發送同一動作的控制項，並由狀態區公告進度。首次請求失敗時呈現含重試操作的錯誤面板；後續請求失敗時保留既有卡片，再顯示錯誤與針對失敗請求的重試操作。只有成功收到零筆資料時才能呈現空結果。

這項區分能避免把網路或驗證失敗誤呈現為沒有課程。首次載入時是否使用骨架卡片是視覺呈現選項，不是另一種資料狀態。

## Implementation Contract

**Behavior:** 已驗證使用者開啟 `/learning/courses/` 時取得課程列表外殼。瀏覽器程式會立即依 URL 中可選的 `q`、`page` 呼叫 `/learning/courses/data/`，只渲染回傳的自有課程、其詳情連結、總數與頁碼控制。搜尋與換頁不會進行文件導覽。

**Interface / data shape:** 成功端點回應為 `{ "items": [{ "id", "name", "code", "owner_display_name", "detail_url" }], "page", "page_size", "total_count", "total_pages" }`。無效頁碼回傳 status 400 JSON，匿名請求回傳 status 401 JSON。其他非成功或無法解析的回應是用戶端可見的載入錯誤，且不得揭露內部實作細節。

**Failure modes:** 首次失敗以錯誤及重試取代列表區；後續失敗會保留最後一次成功列表，並呈現錯誤及重試。成功的零筆回應呈現相應空狀態。較舊請求的回應若在較新搜尋或換頁請求後才抵達，用戶端不得套用它。

**Acceptance criteria:** Django 測試驗證所有權隔離、搜尋、每頁 10 筆、JSON 錯誤回應及無效頁碼。瀏覽器導向測試或可重現的頁面檢查驗證 AJAX 端點設定及狀態容器存在。手動驗證載入、空結果、首次失敗、後續失敗、重試、換頁、搜尋、鍵盤焦點與螢幕閱讀器狀態公告皆符合契約。

**In scope:** learning 的 views、routes、課程列表模板及其頁面專屬靜態資產，以及 learning 測試。

**Out of scope:** 課程資料遷移、課程詳情／建立頁變更、共用前端元件函式庫，以及改造既有靜態清單。

## Risks / Trade-offs

- [JavaScript 在請求前不可用或失敗] → 頁面無法顯示動態課程列表；初始外殼保留明確的載入／錯誤區域，而此變更刻意將 AJAX 視為必要的列表傳遞方式。
- [較舊回應晚於較新請求完成] → 追蹤有效請求或請求序號，並在渲染前丟棄已被取代的回應。
- [列表外殼載入後 session 失效] → 端點回傳 JSON 401，並呈現可理解的錯誤狀態，不能把登入 HTML 當作課程資料渲染。
- [固定筆數的頁碼導覽在大量課程時不易使用] → 分頁資訊維持明確，後續可在不改變擁有權篩選的前提下，另立變更調整導覽呈現或分頁策略。

## Migration Plan

1. 先新增 JSON 端點、路由及端點測試，保留既有頁面路由。
2. 將伺服器渲染的課程卡片迴圈替換為 AJAX 列表外殼、用戶端行為、狀態樣式及頁面測試。
3. 發布前驗證已驗證讀取、搜尋、分頁、重試、所有權隔離與匿名端點行為。
4. 若需復原，可還原既有伺服器渲染卡片迴圈並移除資料端點路由；此變更不涉及資料庫遷移或持久化用戶端狀態。
