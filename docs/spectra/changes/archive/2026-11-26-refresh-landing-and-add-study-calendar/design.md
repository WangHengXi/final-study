## Context

StudyTrack 目前以公開首頁介紹課程、章節、錯題與複習設定；登入成功後由 `LOGIN_REDIRECT_URL` 導向課程列表。課程、章節與錯題皆已有使用者擁有權檢查，但沒有可記錄日期或每日讀書內容的資料模型。首頁的 CSS 將粉紅、鼠尾草綠與紫色混用，示意文字也偏向中學課程。

這次變更需同時更新公開入口的視覺語氣，以及讓登入使用者從每日安排開始使用既有課程整理功能。既有的課程、章節、錯題與複習設定行為不可受影響。

## Goals / Non-Goals

**Goals:**

- 提供成熟、低飽和的莫蘭迪紫白公開首頁，文案與示例面向自主備考者。
- 讓登入成功的使用者先看到今日讀書事項與可前往行事曆、課程的備考首頁。
- 讓使用者在月曆中建立、查看、編輯、完成與刪除屬於自己的單日讀書事項。
- 允許讀書事項選擇關聯自己的既有課程，亦可建立未關聯課程的安排。

**Non-Goals:**

- 不實作重複事項、通知、外部日曆同步、拖放排程、讀書時數計時或統計圖表。
- 不改變既有課程、章節、題目、標籤與複習設定的資料結構或流程。
- 不將公開首頁限定為單一考試名稱，且不以不存在的進度或正確率統計作為功能宣稱。

## Decisions

### Separate public landing page from authenticated study dashboard

根路徑維持公開首頁，讓訪客可認識服務並登入或註冊；登入使用者在根路徑則導向或渲染備考首頁。登入成功後的預設導向改為備考首頁。備考首頁顯示今天的日期、當日未完成及已完成事項，並提供「新增今日安排」、「查看行事曆」與「我的課程」入口。

這個做法將行銷／說明內容與個人資料清楚分開，且符合使用者希望把「每天要讀的東西」放在登入後首頁的方向。替代方案是把行事曆直接塞進公開首頁；它會混合訪客說明與私人資料，且不能處理登入前資料缺失，因此不採用。

### Store daily study tasks with user-owned dates

在 learning app 新增 `StudyTask` 資料：`owner`（必填使用者）、`scheduled_date`（必填日期）、`title`（必填，最多 120 字）、`course`（可選，僅能指向 owner 的 Course）、`notes`（可選文字）、`is_completed`（布林值，預設 false）、建立與更新時間。單日可有多筆事項；不設定同日唯一限制。資料依日期、完成狀態與建立時間排序。

所有讀取與寫入都以登入使用者為篩選條件。若 URL 指定不屬於該使用者的事項，回應 404；若提交其他使用者的課程，表單驗證失敗且不寫入資料。替代方案是把內容存進 CourseSetting；該模型是每課一筆的複習偏好，無法表達日期、跨課程安排或多個同日事項，因此不採用。

### Server-render a monthly calendar with accessible task controls

行事曆以 `GET /learning/calendar/?month=YYYY-MM` 顯示指定月份；未帶 month 時顯示當月。頁面提供前後月連結、每個日期格中的事項摘要、以及前往新增事項的入口。無效 month 不應造成伺服器錯誤，改回當月並讓頁面仍可使用。

新增與編輯使用伺服器渲染表單；完成狀態以受 CSRF 保護的 POST 操作切換；刪除也使用 POST。這延續現有 Django 表單和 POST-redirect-GET 模式，無須加入前端框架。替代方案是 AJAX 行事曆；目前沒有拖放或即時更新需求，會增加不必要的 API 與狀態複雜度，因此不採用。

### Use a single Morandi purple and white visual system

公開首頁、備考首頁與行事曆使用共同的低飽和紫白視覺：暖白背景 `#FAF9FC`、主要灰紫 `#766782`、深色文字 `#403849`、淡紫表面 `#EEEAF2`、邊框 `#DDD5E4`。主要圓角為 16px，按鈕圓角為 999px，卡片間距維持 16px 或 24px。公開首頁移除粉、綠、多色交錯卡片、便條紙與中學科目示意，改用單色層次和中性備考文案。

此決定直接回應「莫蘭迪紫色和白」與較成熟的定位。替代方案是保留多色卡片、僅替換示例文字；它仍會傳達手帳／校園感，因此不採用。

## Implementation Contract

**可觀察行為與介面：**

- 未登入訪客請求 `/` 時看見紫白公開首頁；首頁僅介紹已存在的課程、章節、錯題、複習設定與即將提供的個人安排入口，不宣稱統計或提醒功能。
- 已登入使用者請求 `/` 及完成登入後，抵達備考首頁；該頁只能顯示該使用者今天的 `StudyTask`，並在沒有事項時顯示明確的空狀態與新增入口。
- `/learning/calendar/` 需要登入。month 參數採 `YYYY-MM`；指定月份的格子只顯示請求使用者的事項。相鄰月份能保留切換目標月份。
- 新增或編輯事項的表單包含日期、標題、可選課程與可選備註；有效提交後回到能看見該事項的日期或月份。標題空白、超過長度、日期不合法或課程不屬於本人時，以可見錯誤回應且不新增／變更資料。
- 事項的完成切換與刪除為 POST 加 CSRF；成功後回到來源頁面或該事項所在月份。其他使用者無法透過 URL、表單欄位或列表取得、變更或刪除事項。
- 共用導覽在登入後提供備考首頁、行事曆、我的課程與 POST 登出；訪客仍能使用首頁、登入與註冊。

**驗收方式：**

- Django 測試涵蓋公開與登入首頁的導向／內容、日曆月份顯示、任務新增與編輯驗證、完成與刪除操作、跨使用者存取拒絕，以及導覽連結。
- 手動確認桌面與窄螢幕下的首頁、備考首頁及月曆，配色僅使用紫白層次且操作控制有可讀文字與鍵盤焦點。

**範圍界線：**

本次包含公開首頁、備考首頁、單日事項與月曆操作；不包含重複排程、提醒、同步、拖放、計時及統計。

## Risks / Trade-offs

- [同時變更多個入口頁面可能讓導覽斷裂] → 以既有 URL 名稱與 Django `reverse` 建立連結，並以導覽與登入導向測試覆蓋。
- [日曆格內事項過多時易擁擠] → 月格只顯示簡短標題，完整編輯操作在事項頁或表單進行；本次不加入複雜的前端展開元件。
- [可選課程欄位可能被竄改] → 在表單 queryset 和儲存端皆限制為目前使用者的課程。
- [資料模型遷移影響現有資料庫] → 新模型與既有表獨立；部署前執行遷移，回復時可還原程式版本且不刪除任務資料。

## Migration Plan

1. 建立並套用新增 `StudyTask` 的資料庫遷移。
2. 部署路由、表單、視圖、模板、導航與登入導向後執行 Django 測試。
3. 手動以兩個帳號驗證資料隔離與月曆操作。
4. 若需回復，還原應用程式版本與登入導向；保留新增資料表，避免刪除使用者已建立的安排。

## Open Questions

無；本次以無時間欄位、無重複規則的單日讀書事項作為第一版範圍。
