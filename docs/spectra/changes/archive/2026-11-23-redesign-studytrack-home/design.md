## Context

StudyTrack 是 Django 專案；公開首頁由 `HomeView` 渲染 `apps/core/templates/core/home.html`，學習區則已支援登入使用者建立與瀏覽課程、章節、錯題、標籤，以及設定目標正確率與複習間隔。目前首頁使用紙張色與柔和色系，但同時呈現重做日期、答對答錯結果、正確率走勢與題目狀態；這些資料與流程沒有對應的資料模型或介面。

本次變更限於公開首頁的介紹與入口。它必須讓第一次到訪者在不閱讀長文的情況下理解產品已能完成什麼，並把已登入者帶往可立即操作的課程列表。

## Goals / Non-Goals

**Goals:**

- 以溫暖文具／手帳感建立可辨識的首頁視覺，並維持 StudyTrack 現有的柔和色彩基調。
- 將首頁敘事收斂為已實作的學習流程：建立課程、整理章節、記錄錯題與錯誤原因、設定複習節奏。
- 將主要行動依登入狀態導向正確下一步，減少已登入者再回到登入頁的摩擦。
- 讓小螢幕、鍵盤操作與減少動態效果偏好仍能完成瀏覽與主要行動。

**Non-Goals:**

- 不建立題目重做紀錄、答題狀態、正確率趨勢、進度分析或其資料模型。
- 不變更課程、章節、錯題、標籤或學習設定的既有流程。
- 不導入設計系統、圖示套件、字型服務或新的前端框架。
- 不重新設計登入、註冊或學習區的頁面。

## Decisions

### Honest feature narrative

首頁只以已存在的資料與工作流程呈現功能。功能卡片以「課程卡、章節清單、錯題便條、複習設定」作為靜態手帳素材，移除正確率、重做結果與分析圖表。這比延續完整儀表板示意更能建立可信預期，也不需要為行銷頁補做尚未排定的分析功能。

替代方案是保留目前三張手機圖並加上「功能示意」註記；不採用，因為畫面仍會暗示可查閱的資料與互動存在。

### Warm stationery composition

首頁使用奶油紙張背景、深灰紫文字、粉紫與鼠尾草綠的輔助色塊、圓角便條與細框線。首屏將價值主張、主按鈕與學習桌面拼貼並置；接續以四步驟手帳流程與簡短功能說明支撐決策。排版採 CSS 與既有 Tailwind CDN，不依賴外部圖片，因此頁面可在目前環境穩定載入且維持輕量。

替代方案是改用真實照片或插畫作為 Hero；不採用，因為專案目前沒有可授權的視覺素材，且會把焦點從使用者可採取的第一步移開。

### Auth-aware primary action

首頁的主要行動顯示「建立我的第一門課」。已登入使用者連至 `learning:course-list`，以便查看或建立課程；未登入訪客連至 `account_login`，沿用現有帳號流程。次要行動捲動至流程介紹，不要求帳號狀態。

替代方案是所有人都一律導向登入頁；不採用，因為已登入使用者會多走一步才能抵達可操作內容。

### Accessible progressive enhancement

首屏與流程內容在沒有 JavaScript 時仍完整可閱讀與可導航。互動只用於不改變核心導覽的輔助效果；可聚焦控制項保有可見焦點，且 `prefers-reduced-motion: reduce` 會關閉非必要動畫或平滑捲動。小螢幕以單欄重排，不能把任何核心內容藏在輪播或懸浮狀態後。

替代方案是以自動輪播展示便條卡；不採用，因為它降低閱讀控制權，也無助於主要轉換行動。

## Implementation Contract

**可觀察行為：**

- 公開首頁 SHALL 在首屏表達「將卡住之處整理為進步」的價值，並提供可辨識的主要行動「建立我的第一門課」。
- 未登入訪客啟用主要行動時 SHALL 前往既有登入頁；已登入使用者啟用相同行動時 SHALL 前往自己的課程列表，從該頁可建立課程。
- 首頁 SHALL 說明課程、章節、錯題／錯誤原因及複習設定，且不得把正確率統計、重做結果、題目狀態或分析圖表描述為目前可用功能。
- 首頁 SHALL 在窄螢幕保留首屏、主要行動與每一步驟的內容；鍵盤使用者 SHALL 能看見連結與按鈕焦點；使用者開啟減少動態效果偏好時 SHALL 不會被平滑捲動或裝飾性動畫干擾。

**介面與資料：**

- 僅使用 Django 模板已有的 `user.is_authenticated` 條件與命名 URL `account_login`、`learning:course-list`；不新增 HTTP 端點、資料欄位或 API 格式。
- `HomeView` 繼續回傳首頁模板；模板自行根據請求使用者決定主要連結。

**失敗與回退：**

- 若 JavaScript 未載入，主要連結與頁面內容仍 SHALL 可用；流程介紹可作為一般錨點或連續頁面內容閱讀。
- 若課程列表為空，既有課程列表頁的空狀態 SHALL 繼續引導使用者建立課程；本次首頁不複製或改變此流程。

**驗收方式：**

- 以未登入與已登入請求檢查首頁主要行動分別產生登入 URL 與課程列表 URL。
- 在桌面與窄螢幕寬度手動檢查首屏、流程卡與主要行動可讀且可操作。
- 使用鍵盤 Tab 檢查連結／按鈕焦點可見；啟用減少動態效果偏好檢查不會強制平滑捲動。
- 檢視首頁文案與示意，不出現正確率百分比、重做結果、題目狀態或進度分析的產品宣稱。

**範圍界線：**

- 範圍包含公開首頁模板及其為導向所需的極小 view／模板條件調整。
- 範圍不包含帳號頁、學習區樣式、資料模型、資料遷移、題目練習或分析功能。

## Risks / Trade-offs

- [手帳裝飾過多造成首屏資訊不清] → 以一個主標、一個主要行動與一個可辨識的學習桌面示意為首屏優先順序，裝飾內容不得搶走文字對比或按鈕可見性。
- [登入後首頁連結的名稱與現有設定不一致] → 實作時以 Django 已註冊的命名 URL 驗證連結，不硬編碼路徑。
- [把尚未實作的功能換成含糊承諾] → 實作與檢查時逐項比對目前的 Course、Chapter、Question、Tag、CourseSetting 模型與已暴露的頁面流程。
- [小螢幕上的拼貼排列擁擠] → 以單欄順序呈現文字與核心便條卡；純裝飾卡可以縮減，但不得移除主要行動或流程資訊。
