## Context

StudyTrack 已有共用主題檔 `apps/core/static/core/studytrack-theme.css`，但課程模板仍保留 Tailwind 任意色值，例如粉色 `#EAD1D7`，而舊有表面色亦包含綠色與玫瑰色。共用主題目前以選擇器覆蓋部分舊色，導致配色來源分散且容易漏網。

本次僅重整使用者看得到的視覺色彩，不改變資料、路由、登入行為、課程／行事曆操作或內容結構。目標使用者是自主備考者與考研生，因此介面需保持克制、成熟、清楚，而非手帳式多色分類。

## Goals / Non-Goals

**Goals:**

- 全站以單一莫蘭迪灰紫與白色層次呈現，不再以粉色、綠色或玫瑰色做裝飾或課程分類。
- 讓公開首頁、備考 Overview、行事曆、任務表單、課程清單、課程詳情與課程表單使用相同色彩角色。
- 保留既有文字對比、鍵盤焦點與錯誤提示的可讀性。
- 消除模板內會直接顯示為粉綠的硬編碼色彩來源，而非僅由後置覆蓋規則掩蓋。

**Non-Goals:**

- 不變更頁面版型、文案、資料模型、URL、表單欄位或任務操作。
- 不新增深色模式、使用者自訂主題、課程分類色或依狀態變色的儀表板。
- 不改造 Tailwind 的建置流程或移除既有 Tailwind CDN。

## Decisions

### Define one tokenized purple-and-white palette

共用主題定義並作為唯一裝飾性色彩來源：頁面背景 `#FAF9FC`、卡片白 `#FFFFFF`、淡灰紫 `#EEEAF2`、主要灰紫 `#766782`、深灰紫文字 `#403849`、輔助文字 `#6F6678`、邊框 `#DDD5E4`，焦點環使用主要灰紫。按鈕、標籤、月曆標頭、事項摘要與課程卡片僅使用這些角色的白／淡紫／灰紫變化。

**Rationale:** 單一低飽和紫色加白色可以建立層級，卻不會讓個人備考工具呈現中學課堂或手帳拼貼感。

**Alternatives considered:** 保留粉綠但降低飽和度；不採用，色相仍與使用者要求衝突。以每門課不同顏色區分；不採用，會重新引入多色視覺噪音。

### Replace source colors instead of relying on CSS overrides

課程模板和頁面 CSS 中的粉綠／玫瑰任意色值改為色彩角色對應的 class 或共用 CSS custom property；共用主題不再列出用來遮蔽已淘汰粉綠色值的選擇器。必要的白底與文字色也映射為上述 token。

**Rationale:** 移除源頭能讓新頁面沿用一致規則，並防止 CSS 載入順序或新 class 讓舊色重現。

**Alternatives considered:** 只增加更高權重的覆蓋選擇器；不採用，維護成本高且無法保證所有頁面一致。

### Preserve semantic feedback without decorative multicolor surfaces

成功、錯誤、停用等必要狀態不得以粉綠卡片、課程圓點或背景色做為唯一線索；保留既有可讀文字、表單錯誤訊息與鍵盤焦點。表單驗證錯誤可維持明確的語意文字色，但不可成為頁面裝飾底色或課程分類色。

**Rationale:** 完全移除可辨識的狀態訊號會傷害可用性；限制它們的用途能同時遵守紫白主視覺。

**Alternatives considered:** 將所有狀態都強制改成同一個紫色；不採用，使用者難以辨識表單錯誤。

### Verify rendered pages and source-level palette boundaries

自動測試確認共用樣式與受影響頁面均載入主題；針對可辨識的淘汰裝飾色建立來源檢查，避免 `#EAD1D7`、舊綠色表面值或粉綠色的課程圓點再次出現。手動在桌面與窄螢幕確認所有目標頁只呈現紫白層次，並確認焦點與表單錯誤仍清楚可見。

**Rationale:** 視覺回歸無法僅靠 Django 回應狀態捕捉，來源邊界檢查加人工檢查可防止最常見的重新引入。

**Alternatives considered:** 只做人工檢查；不採用，之後編輯模板時很容易再加入舊色。

## Implementation Contract

**可觀察行為：**

- 訪客首頁、登入後 Overview、行事曆與所有課程相關頁面使用白底、淡灰紫表面、灰紫互動控制、深灰紫文字與一致邊框；不顯示粉紅、綠色、玫瑰色或多色課程標記。
- 課程、行事曆事項與導覽項目的差異由文字、位置、邊框、白／淡紫表面與灰紫焦點表達，不依賴各自不同色相。
- 互動 hover、鍵盤 focus、disabled 狀態及表單錯誤保持可辨識；錯誤訊息不使用裝飾性色塊。
- HTML 和 CSS 不保留已淘汰的裝飾色值或專為覆蓋那些色值而存在的規則；純黑白、透明度、陰影與必要的表單錯誤文字色不受此限制。

**驗收方式：**

- Django 測試確認首頁、Overview、行事曆與課程頁的共用主題資產仍被載入，並檢查淘汰裝飾色未出現在指定模板與 CSS 來源。
- 手動檢查桌面與窄螢幕的首頁、Overview、月曆、課程清單、課程詳情與新增／編輯表單；所有裝飾表面與主要互動控制僅為白、淡灰紫或灰紫。
- 以鍵盤依序聚焦連結、按鈕與欄位，並提交空白必填欄位，確認焦點與錯誤訊息可讀。

**範圍界線：**

本變更涵蓋受影響頁面的裝飾色與其來源檢查；不涵蓋資料功能、頁面內容重寫、深色模式、每課顏色、圖表或後端 API。

## Risks / Trade-offs

- [將任意色值直接替換可能降低局部文字對比] → 以深灰紫文字、淡紫表面與鍵盤／錯誤人工檢查確認可讀性。
- [Tailwind 任意色值散落於模板而遺漏] → 搜尋受影響模板的色值並用來源檢查防止已知淘汰色回歸。
- [移除覆蓋規則後有未遷移頁面顯露舊色] → 先遷移所有提案列出的頁面，再刪除只為舊色服務的覆蓋規則。

## Migration Plan

1. 先更新共用色彩 token 與首頁、導覽、行事曆樣式。
2. 將課程相關模板的裝飾性色彩改為對應 token 或共用樣式。
3. 移除已淘汰粉綠色的覆蓋規則，並新增來源／資產測試。
4. 執行完整 Django 測試，完成桌面與窄螢幕的手動顏色、焦點與錯誤檢查。
5. 若需回復，還原本次 CSS 與模板版本；本變更不涉及資料遷移或資料刪除。
